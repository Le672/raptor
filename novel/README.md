# Yukino Novel · 轻小说书房

独立轻小说网站，正式入口为 https://novel.yukino.bond 。沿用 Yukino 品牌与视觉，导航围绕轻小说书房并提供返回主站入口；使用主站现有 React、Vite 和 lucide-react 依赖、独立 Cloudflare Worker 与静态资源。书目、介绍、目录与搜索公开浏览；章节正文与手动同步需要 Yukino 主站账户登录，登录后返回原页面。

## 本地运行

从仓库根目录执行：

```powershell
pnpm install
pnpm novel:dev
```

在 Chrome 打开 http://127.0.0.1:5186 。本地服务通过已配置的 HTTP(S) 代理访问公开书源，缓存保存在忽略的 `.novel-work/local-kv`。生产使用 Cloudflare KV。

```powershell
pnpm novel:test
pnpm novel:build
```

## 数据与更新

| 书源 | 搜索范围 | 目录与阅读 |
| --- | --- | --- |
| 哔哩轻小说 | [lnovel 公开聚合接口](https://github.com/yjl9903/lnovel/blob/main/examples/api.http)已索引的译文书库 | 分卷、正文、插图 |
| 菠萝包 SF | 源站当前返回的公开搜索结果 | 免费章节；VIP 明确标注并链接源站订阅 |
| 轻之文库 | 源站当前返回的公开搜索结果 | 公开作品、分卷与正文 |
| 轻小说文库 | 书籍链接直达、已知公开书目中的本地搜索 | 可访问时读取公开目录与正文；生产实测源站限制 Cloudflare 服务器访问，当前提供源站阅读入口；全站匿名搜索需要登录 |

- 各适配器独立编写，HTML 用 parse5 解析，文库 GBK 页面由 TextDecoder 解码，没有复制第三方解析器代码。页面结构、访问验证和源站状态可能变化，逐源显示失败、受限、旧缓存和最近成功时间。
- 最近更新页汇总各源当前更新列表和已打开书目的公开元数据，**不是四个平台的全部作品**。搜索返回哔哩索引、SF/轻之文库源站第一页公开匹配、已知文库书目，再统一筛选和分页。显示实际返回范围和数量，不写死总书量。
- Cloudflare Cron 每小时第 40 分钟同步更新列表，并对三个新增书源各轮流检查一本已知书目，给免费 Worker 的 fetch 与 Cache API 共用子请求额度留出余量；书架每次最多检查六本新增书源作品，按上次成功获取时间轮换。目录与书目缓存 5 分钟、章节缓存 15 分钟，手动刷新最短 1 分钟。源站发布、翻译与上游缓存决定实际更新速度，不承诺与源站同步秒更。
- 本站同步时间、源站更新时间、上游抓取时间分别保留。失败时保留旧快照并明确显示原因和成功时间；空索引、登录 HTML、错误 JSON 不会覆盖成功快照。
- KV 只由上述定时任务写入一个合并索引快照：每次最多 1 次 put，按配置每天 24 次；固定包含索引、已知书目与源健康共七个键，不包含任意搜索或正文。访客的访问、刷新、搜索、详情和章节读取只写有界内存与 Cloudflare Cache API，不再增加 KV 写入；旧 KV 键保留只读回退。相同实例的定时任务合并并按小时去重，Cloudflare 在不同实例重复投递定时事件仍可能重复写入；KV 不提供原子锁。
- 索引记录从原始成功时间起最多保留 30 天，源健康 1 小时；只有成功数据比旧快照更新才持久化，全部书源失败或只有新的错误健康记录时不重写、不续期。临时内存上限 128 条 / 16 MiB，单条最多 8 MiB；Cache API 是可被平台逐出的地区缓存，搜索保留 1 小时、正文 7 天，读取缓存不会重置原始过期时间。新打开的书目尽力记入临时已知书目，仅定时任务所在实例/地区可见的条目会进入下一次持久快照；浏览器书架和直达链接继续可用。KV 或 Cache API 写入失败不把已成功获取的正文变成错误，定时持久化失败单独记录，设置页与 `/api/status` 返回最后成功快照时间和状态，不伪报已保存。
- 浏览器最近 180 个成功的公开 API 响应可在断网时回退。正文不再写入或回退浏览器响应缓存，升级时只清理原正文响应；需要联网验证登录后阅读，401 和手动同步失败均不会拿旧缓存冒充成功。书架、阅读进度、公开书目缓存与用户已下载的 TXT 文件保留。新增源章节明确拒绝访问时，服务端也不回退旧正文。Service Worker 缓存应用外壳；插图由普通浏览器 HTTP 缓存决定离线可用性。
- `done` 表示上游整理任务完成，不代表小说完结；连载状态只依据上游明确标签。
- 旧哔哩书号、缓存键和书架 schema 保持兼容。新增书号使用 `sf-`、`linovel-`、`wenku-` 前缀，各书源分开存进度；“其他书源”只给出匹配候选，需核对作者与目录，不猜测章节对齐。

## API

- `GET /api/books?source=all&q=关键词&tag=题材&status=ongoing&page=1&sort=updated`，`source` 可为 `all`、`bili`、`sf`、`linovel`、`wenku`；分页固定 24 本，支持 `updated`、`title`、`new`（源内数字编号由新到旧）。
- `GET /api/books?ids=8,sf-775221,linovel-122429,wenku-1973`，为书架检查更新。
- `GET /api/book/:id`、`GET /api/book/:id/volume/:vid`、`GET /api/book/:id/chapter/:cid`。
- `GET /api/status`，索引数量、各源状态/范围/成功时间、最近同步和最新源站更新；`refresh=1` 请求检查。
- 图片代理仅允许四个书源已验证的 CDN 图片目录与栅格格式，不接受任意网址、端口、凭据或重定向。正文转成文字/图片块，由 React 渲染，拒绝外部脚本、事件属性和 iframe。

## 部署

`.github/workflows/deploy-novel.yml` 复用仓库现有 Cloudflare secrets，建立专用 `yukino-novel-cache` KV，部署 `yukino-novel` Worker、静态资源、每小时 Cron 和 `novel.yukino.bond` 自定义域名。同步部署可通过 `yukino-novel.3584643854.workers.dev` 访问。

部署脚本不读取、写入或打印凭据内容。`novel/.deploy/wrangler.json` 是忽略的运行时配置，KV ID 自动写入。部署后的 `verify-novel-live.mjs` 检查网站外壳、逐源状态、真实中文搜索、公开目录与免费章节标注，并验证匿名正文和手动刷新返回 401 登录提示；该匿名检查不能代替真实账户登录后的正文验收。每次可见变更同步主站 `Changelog.tsx`。

书架与阅读足迹只在本机保存，不会上传给书源；备份仅含书目与进度。正文和插图权利归原作者与相关权利人，支持正版作品。
