# Workers KV 写入预算

Cloudflare 免费 KV 的每天 1,000 次写入额度由整个账号共享，不是每个站点或命名空间各有 1,000 次。限额在 UTC 00:00（新加坡/北京时间 08:00）重置，已经消耗的次数不能由部署清零。

## 内容站预算

| 服务 | 每小时任务（UTC） | 每次最多写入 | 正常计划每日最多写入 |
| --- | --- | ---: | ---: |
| 影视馆 | 整点 | 8 个片源各一份快照 | 192 |
| 番剧放映室 | 第 20 分钟 | 4 个番源各一份快照 | 96 |
| 轻小说书房 | 第 40 分钟 | 7 个固定索引/状态键合为一份快照 | 24 |
| 合计 | | | **312** |

首页、搜索、详情、正文、封面和手动刷新不会持久写入 KV。内容站的临时数据放在有界内存或 Cache API；Cache API 不属于 Workers KV。定时任务只保存固定首页/索引快照，源站失败时保留旧快照原时间，过期数据不冒充新数据。已有 KV 键不删除。

312 是当前正常计划的上限，不是整个账号的实时计量；跨实例重复投递任务、管理员操作、邮箱和其他远端 Worker 仍可能额外写入。账号剩余预算应优先留给邮箱登录、设置、发送统计和附件，不能因为每个内容站单独低于 1,000 就认为账号安全。

`npm run kv:budget` 检查三个配置只保留每小时一次任务，并将内容站的合计预算限制为每天 500 次以内。三个内容站部署前都会执行；各站服务测试实际统计定时任务和访客接口的 KV 写入次数。新增片源或提高频率前必须复核合计预算。

## 超额当天的行为

成功取到的实时目录和正文照常返回，KV 保存失败单独记录，不能把成功阅读变成接口错误。仍可读取的旧快照作为失败回退，并显示其实际检查时间。轻小说状态页分别报告上次成功持久化时间和当前保存失败原因。

不使用 KV 为每个请求记录限速或点击数，也不通过自动注册/拆分账号规避配额。强制登录不会减少后台 Cron 写入，而且现有邮箱登录本身要写 KV，因此本次先消除不必要的缓存写入。跨子域登录保护需后端验证主站身份，不能只隐藏按钮。

参考：[Cloudflare KV 额度和重置说明](https://developers.cloudflare.com/kv/platform/pricing/)、[Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/)。
