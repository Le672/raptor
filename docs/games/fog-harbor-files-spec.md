## 1. 游戏定位

### 1.1 一句话介绍

一名档案员死在旧港档案馆里。几分钟前，大厅里的所有人还听见他宣布，明早将移交全部原件。玩家需要查清那段声音究竟证明了什么，并找到八年前一场码头火灾被删掉的证词。

### 1.2 希望玩家获得的体验

1. **自己提出解释。** 先发现问题，再找证据验证；不能只是读完故事后选一个名字。
2. **推理能复查。** 关键结论可以点开查看依据，记录与证言发生冲突时有明确原因。
3. **人物有各自的生活。** 嫌疑人会为不同的事撒谎，隐瞒旧案、违规借卡或争执，与杀人分开判断。
4. **反转改变理解。** 同一段声音、同一句话，在查清来源后意义改变；不靠突然出现的新人物翻案。
5. **完成一个完整故事。** 首案交代凶手、手段、动机、旧案责任和人物去向，不把主要答案留给续作。

### 1.3 不进入首发的内容

联机、狼人杀式阵营对抗、随机凶手、抽卡、体力、付费买提示、战斗、开放世界、全角色配音，以及无限自由对话。以后可以增加新案件，但首案必须独立成立。

## 2. 核心玩法

### 2.1 基本循环

进入地点 → 观察物件或记录 → 取得证据 → 询问相关人物 → 标记矛盾 → 形成可验证的结论 → 回到现场核验 → 提交调查报告。

玩家可以在开放地点之间自由切换。章节控制内容出现的时机，不能强迫所有人按同一条点击顺序收集线索。

### 2.2 场景调查

- 每个地点有完整背景、可辨识的物件和人物站位。
- 首次进入先显示场景，文字说明跟随玩家的观察出现。
- 物件支持观察、放大、翻面、查看附件等与内容有关的动作。
- 关键区域不得靠逐像素寻找。可主动开启热点提示；热点提示不扣分。
- 搜过的物件保留状态，并允许再次阅读。出现新上下文时明确标记“可重新核对”。
- 不能用“再点同一处五次”解锁内容。
- 放大图中的正文必须能展开为可选取、可缩放的文字。

### 2.3 对话与质询

每名人物都有基础话题、已记录证言和证据质询入口。玩家可以选择“针对这句话出示证据”，也可以先选证据再询问相关人物。

出示错误证据时，反馈需说明关联不足的原因，例如：“这份记录说明卡片被使用，尚不能确定是谁拿着卡。”不能只弹“错误”。

质询针对具体命题，不要求玩家猜中某个话题的固定排列顺序。有效证据的不同出示顺序应能进入同一段已确认的剧情。

### 2.4 证据、证言与推测

| 类型 | 表示什么 | 界面要求 |
|---|---|---|
| 物证与原始记录 | 玩家实际取得的对象、照片、日志、录音等 | 显示来源、取得位置、原始文本和相关时间 |
| 证言 | 某个人声称的事情 | 显示说话人、原话和目前的核验状态 |
| 观察 | 对证据的直接描述 | 能回到对应图像、文本或音轨 |
| 推测 | 玩家当前的解释 | 可以修改或撤回，不自动变成事实 |
| 已证实结论 | 有充分依据支持的有限命题 | 显示支持项与适用范围，不扩大含义 |

例如，“有人使用沈砚的卡进入”不能自动写成“沈砚进入”。“听见声音”不能自动写成“本人当时活着”。

### 2.5 推理板

- 提供“主张—依据—反证”结构，支持自由摆放笔记，也提供手机列表视图。
- 核心推理采用语义选项与证据槽位，避免依赖中文关键词匹配。
- 一个结论可接受多组等价且充分的证据；无关附加证据不抵消有效证明。
- 有意义的中间结论可以保存为“尚未证实”。没有证据时猜中凶手不会判定破案。
- 不让玩家把任意两张卡片两两穷举；操作围绕明确问题，例如“这段声音能否作为存活证明”。
- 玩家不必先手动完成所有节点。提交报告时，系统可以根据已收集证据验证等价的完整推理。

### 2.6 时间线

- 记录区分事件发生时间、记录时间、证人回忆时间。
- 允许时间点、时间区间和先后关系，未知时间保持未知。
- 拖动不是必需操作；手机与键盘用户可以点选事件后选择位置。
- 冲突只在相关依据已经取得时提示，不提前泄露未发现的事实。
- “推定死亡时间”不能被写成精确到秒的医学结论。

### 2.7 提示与难度

不通过删减关键证据提高难度。三种辅助设置只改变引导强度，可以随时调整。

| 设置 | 行为 |
|---|---|
| 引导 | 显示待核验的问题、相关地点和可继续询问的人物 |
| 标准 | 显示当前目标；由玩家主动查看提示 |
| 专注 | 减少未读标记和关系提示，仍保留完整无障碍支持 |

每个推理问题提供三级提示：指出应关注的矛盾 → 指出可核对的材料 → 给出明确的下一步。第三级提示在展开前提示包含解法。

提示免费，无次数限制。使用提示只记录在通关回顾中，不阻止任何剧情结局。

### 2.8 失败与恢复

- 无实时倒计时，不会因为读得慢而死人或错过唯一线索。
- 错误质询可继续修正；错误指认进入可返回的报告复核，不删除存档。
- 涉及进入结局、重开案件、覆盖存档的操作需要明确确认。
- 允许提前提交尚不充分的理论；反馈“缺少哪类支持”，不直接公布正确答案。

## 3. 内容规模与节奏

| 内容 | 首案范围 |
|---|---|
| 章节 | 5 章，包含开场调查与结案 |
| 主要调查人物 | 6 人；其中 4 人是主要嫌疑人，另外 2 人也接受时间线核查 |
| 地点 | 7 个，包含可放大的子场景 |
| 证据 | 32 项，每项编号固定，详见第 15 节 |
| 核心证言 | 24 条，详见第 16 节；普通对话另计 |
| 主要推理 | 8 个：今案 6 个，旧案 2 个 |
| 结局 | 2 个正式调查结果，另有 1 个错误指认后的复核段落 |
| 正式游戏文本目标 | 约 2.5—4 万汉字，包含证据原文、分支对话和回顾；按信息密度控制，不为凑字数重复说明 |
| 音频 | 雨声、港区环境、广播、关键录音片段；所有必要信息有完整文字替代 |

本稿固定主要事实、关键场景、线索目录与解法，不冒充已经写完的全部运行时对白。开发前需要把各证据原文、全部话题分支和逐屏交互补入内容包；补写只能表达既定事实，不得临时增加决定谜底的新事实。

### 3.1 五章结构

| 章节 | 目标时长 | 玩家面对的问题 | 章节完成后的认识 |
|---|---|---|---|
| 第一章：闭馆以后 | 20—30 分钟 | 刚刚还在讲话的人为什么死在档案室？ | “所有人都听到了”不等于已经确定死亡时间 |
| 第二章：声音的来源 | 25—40 分钟 | 广播究竟来自哪里？ | 广播可以被解释，原先的时间判断需要重建 |
| 第三章：借出去的名字 | 40—55 分钟 | 门禁卡、持卡者与行程能否对应？ | 多个人在撒谎，但说谎内容不同 |
| 第四章：没有删掉的部分 | 40—65 分钟 | 今案的物证如何闭合？旧录音为什么有两个版本？ | 当前凶案与旧案的责任需要分别证明 |
| 第五章：把名字写回来 | 20—35 分钟 | 哪些结论足以写入正式报告？ | 证据链完成，人物得到与事实相符的尾声 |

首次试玩后调整时长。若实际只是几十分钟的点击流程，应补充有效调查与人物内容，不能靠慢速打字延长。

## 4. 无剧透故事简介

2016 年 11 月，潮汐市旧港区拆迁。海事档案馆将在月底闭馆，一批旧录音要在移交前完成整理。

八年前，第七码头发生火灾。事故调查认定，值班员许长川没有及时请求停止接驳。许长川在救援中身亡，六名遇难者的家属，此后各自带着一份没有说服自己的报告生活。

档案员顾承舟找到一卷尚未公开的母带，约来当年的相关人员、修复师，以及许长川的女儿。原件将在第二天移交独立调查机构。

当晚 20:14，大厅广播传出顾承舟的声音：“所有原件，明早一并移交。今晚谁也别碰。”

四分钟后，他被发现死在档案室。

玩家扮演刑警林砚，在夜间调查中核对现场与留存记录。雨让旧港变得安静，几个人却都在争着解释那段声音。

| 沈砚，30 岁 | 档案馆夜间安保 | 负责限制区域的出入管理 | 紧张，急于强调门禁完整有效 |

## 6. 地点与界面

### 6.1 七个地点

| 地点 | 场景用途 | 主要交互 |
|---|---|---|
| 前厅与签收台 | 人物初次集中、广播出现、签收与照片 | 查阅登记、调取大厅录像、询问唐素与许知微 |
| 档案室 | 当前凶案现场 | 观察现场、检查门窗、查看镇纸和工作证残片 |
| 录音修复间 | 声音诡计与周予安的工作区域 | 查看播放列表、工作录像、放大工作证、核对音轨 |
| 安保值班室 | 门禁和时钟基准 | 比对出入事件、借卡记录、钥匙与应急开门记录 |
| 馆务办公室 | 罗启明的行程与旧案文件 | 查看会议原始录像、旧批注和往来函件 |
| 地下泵房 | 沈砚、何闻的行程 | 核对安全录像、确认进出范围、了解旧库房材料去向 |
| 移交整理台 | 旧案原件、最后复核与报告 | 比对母带和公布带、查看值班簿、整理报告 |

地点之间通过馆内平面图移动。修复间内部的播音设备台、安保室可调取的机房检修记录作为子场景，不额外增加可移动地点。

### 6.2 桌面布局

中央为完整场景；底部是克制的对话区；侧边可以展开档案夹。时间线、人物与推理板是覆盖式工作区，关闭后回到原位置。主界面保留案件名、保存状态与当前地点，不堆叠无关指标。

### 6.3 手机布局

竖屏为完整可玩模式。底部提供“现场 / 人物 / 证据 / 推理”四个主要入口；场景可平移放大，对话可以展开。长文阅读时隐藏非必要装饰，保留返回位置。

证据出示、时间线编排、放大物件都能通过点选完成，不要求拖拽。所有主要按钮触控区域至少 44×44 CSS 像素；正文默认不小于 16px。

## 7. 美术与声音标准

### 7.1 美术方向

写实插画式旧港档案馆：潮湿玻璃、褪色墙面、旧木柜、磨损金属、暖色台灯。场景采用统一透视与光源，人物和物件属于同一个世界。

界面使用深灰蓝、暗木色和少量暖白纸张。红色只用于标注矛盾、封条或重要状态。纸张具有合适的边缘与纹理，但正文必须清晰。

质量要求：

- 开场、档案室、修复间各有可作为正式游戏画面的完整构图。
- 场景中的门、窗、桌面和证物位置必须与地图及剧本一致。
- 关键工作证、残片、镇纸、播放器接线必须有专门的可放大素材，不能靠描述补救画错的细节。
- 工作证的缺口形状在所有画面中保持一致；正确的高分辨率细节另做人工校对。
- 人物立绘有稳定的脸、服装、年龄和有限表情变化，不出现跨场景换脸。
- 不把默认网页卡片、发光渐变背景或大量圆角统计块当作主游戏画面。
- 若使用生成式素材，只用于可人工校对的画面；证据文字、编号、时钟和断口几何使用确定性制作。

### 7.2 声音方向

以雨、排水泵、老电器底噪和远处船笛建立空间感。音乐在阅读关键材料时降低存在感。开始播放声音前由玩家主动交互授权，提供独立音量、静音与停止操作。

推理中的录音比对同时给出音轨、文字转录和事件标记。听力、设备音质或是否佩戴耳机都不得决定能否通关；波形不是装饰，也不能要求玩家真的具备声学鉴定知识。

## 8. 存档、账号与离线

### 8.1 本地优先

- 进入即可游玩，完整首案不要求登录。
- 收集证据、更新证言、保存推测、完成关键对话和切换章节时写入 IndexedDB。
- 保存采用事务和有序队列；不把卸载页面时的最后一次写入当作唯一保障。
- 至少保留当前自动存档、上一章节检查点及手动存档；可导入、导出文件。
- 清除本站数据会删除本地进度，需在相关设置中准确说明。
- 保存失败有明确提示与导出入口，不能显示“已保存”。

### 8.2 主站登录和云同步

延续已有 games 账号体验：复用主站会话，不增加另一套注册。首次启用同步时由玩家选择；不自动把公共设备上的访客进度上传到刚登录的账号。

云端保存剧情状态、证据与笔记、设置和必要的版本信息；不上传场景素材。状态必须区分“本地已保存”“等待同步”“已同步”“离线”“发生冲突”“同步不可用”。

并发写入使用 revision 校验。两台设备的分歧不能静默覆盖，也不能把证据集合简单取并集——这样会让早期进度凭空获得剧透。冲突页面展示章节与保存时间，并允许保留两份。

账号切换、退出、会话过期时，待上传队列与账号绑定。旧账号的队列不能随新会话上传。云服务不可用不影响本地游戏。

### 8.3 离线与版本

完整案件素材包下载成功并验证后，可离线继续首案。素材未下载时明确说明缺少哪一部分，不宣称首次访问即可全程离线。

剧本发布后以内容版本冻结。更新必须保留旧进度依赖的内容版本，或提供经过验证的迁移；不在同一存档中悄悄更改凶手、时间线或证据意义。服务工作线程的缓存范围必须限定在本游戏，不能接管其他 games 页面。

## 9. 无剧透验收标准

1. 玩完整案后能解释：谁实施杀人、何时有机会、如何制造错误判断、为什么杀人，以及八年前的录音被怎样处理。
2. 必须在最终指认前取得所有决定性事实。凶手承认只能补充情绪与经过，不能填上证明缺口。
3. 首案有完整结尾，不以“真正幕后黑手另有其人”推翻已完成的解答。
4. 手机竖屏、电脑、无声音、键盘操作均可完成。
5. 任意开放顺序不会永久漏掉必要线索；重复询问不会污染状态。
6. 两个正式结果由查明的事实决定，提示次数、阅读速度、语气选择不改变真相。
7. 美术中的空间与道具必须服从推理，不允许好看但逻辑不一致。

## 10. 剧透区：案件的固定事实

**从这里开始包含完整谜底。想保留亲自游玩的体验，可先停止阅读。**

### 10.1 当前凶案

凶手是**周予安**。

她在 20:09:42 使用借来的沈砚的门禁卡进入档案室，借口核对移交材料接近顾承舟，以现场铜镇纸实施致命袭击，20:11:18 按出门按钮离开。20:12:06 起，她出现在修复间的连续工作录像里。

20:14 的广播播放的是顾承舟在 20:02 录下的彩排片段。播放任务原本属于当晚的广播演示流程；周予安在杀人后将这次演示变成了制造“他在 20:14 仍活着”的工具。

彩排与定时任务只写在设备台内的工程流程单上，由顾承舟与周予安处理，没有向前厅人员宣布。广播内容沿用了顾承舟平时闭馆通知的口吻，因此其他人最初误认成实时通知；录制、定时播放的能力则在第二章直接向玩家公开。

广播并不改变门禁，也不让尸体晚些死亡。诡计利用的是人们把说话声音误认作实时发声。

进入档案室后，顾承舟抓住周予安的临时工作证，工作证的一角断裂并留在现场。断口、编号印线和 20:08:54 拍下的完整工作证共同证明，这是今夜新产生的接触痕迹。

**作案没有现场共犯。** 罗启明在旧案中有责任，但没有与周予安共同策划今夜的杀人；其他人的隐瞒不构成今案共犯。剧本不引入未登场凶手、隐藏通道、伪装替身、声音合成或未提示的遥控装置。

### 10.2 八年前的旧案

2008 年 9 月 17 日，第七码头火灾中六人遇难，包括值班员许长川。

许长川在 19:42 已明确请求停止接驳、疏散引桥。罗启明为保住项目经营并逃避对自身管理行为的追查，事后要求周予安处理对外提交的录音。

周予安删去这段请求，并将许长川同夜更早一次正常调度中的“照常接驳”移入摘要。公开版本让听者误以为，他在危险出现后仍要求继续作业。旧报告据此将主要责任压到死者身上。

独立船务值班簿记下了 19:42 收到的停止接驳请求，与原始母带相互印证。修复底稿记下了周予安的编辑，罗启明的书面批注明确提出删改要求。声音有变化、是谁执行、谁下达要求，分别有证据支持。

顾承舟当年接收材料时，把剪辑版本按原始材料登记。他不是今夜唯一的正义人物。他现在准备移交原件，也准备承认自己的签收错误。

何闻曾违反处理要求保留母带；这让原始声音留了下来，也意味着他八年没有把它公开。保留证据与长期沉默同时成立。

首案对旧案还原的是录音篡改与责任转嫁的核心事实。上述材料不凭空证明火灾每个工程环节的原因，事故责任的正式认定由复查处理。

### 10.3 杀人动机

周予安知道，原始母带、修复底稿及交接记录将一起移交。她不能再用“当年只是普通降噪”解释剪辑，也无法把全部责任推给罗启明。

她想让顾承舟撤下能关联到自己的底稿，以为还可以私下改变移交内容。顾承舟拒绝，并告诉她材料已登记封存。她在冲突中选择实施致命袭击，随后利用原有的定时广播与后续工作录像掩饰行程。

20:04 配置正常任务不能被写成“那时已经决定杀人”的证据。她杀人后的误导是机会性的补救，现场和设备记录没有被她神奇地清除。杀人也没有消灭已封存的原件与副本；她想阻止公开的愿望，与实际能否阻止公开分开呈现。

她当年受到上级压力是人物背景，不免除她对剪辑及今夜杀人的责任。结尾不以一句“都是被逼的”替她解脱。

## 11. 建筑、权限和计时约束

### 11.1 档案室出入

档案室位于三楼，只有一扇正常出入口，窗外无阳台或连通建筑。窗户结构与现场状态在第一章展示。不存在暗门、通风井进出或可供人员绕行的路线。

门禁进门需要有效卡或受管理的机械钥匙。门内有合法的紧急出门按钮，出门不会把人锁死。系统分别记录刷卡、开门、关门、出门按钮和机械开锁事件。

**出门按钮记录没有持卡者身份。** 日志中 20:11:18 的含义只能是有人由内向外开门，不能写成“沈砚的卡出门”。

当晚卡片清单、借卡记录、机械钥匙保管与门状态记录全部可查。故事不靠突然声称存在未登记复制卡来改变解答；如果实施中增设别的进出方式，必须重新验证整案。

### 11.2 空间和行程

- 从档案室外门到修复间，按普通步速实测路线约 42—48 秒。
- 周予安 20:11:18 出门，20:12:06 出现在修复间，时间可成立。
- 从地下泵房或办公室视频会议的固定位置到档案室，不能在对应连续录像的正常动作间隙完成往返和袭击。
- 路线与时间在调查界面可查看，不要求玩家从美术尺寸自行换算。
- NPC 在调查阶段的站位不代表案发阶段的位置。时间线始终显示他们当时在哪里。

### 11.3 时间可信度

门禁与录像设备的时间已在当晚例行校对中与同一基准比较，差异不超过 1 秒。校对记录是 E10，第二章起可取得。人物口述的“大约”仍保留为区间。

核心区间按可靠观察写作“20:09:10 最后确认存活，至 20:18 发现死亡”。不借尸温等检查推出精确分钟，更不把周予安的进入时间直接当作医学死亡时间。

录像使用调查人员提取的连续原始片段，并展示提取范围、连续性与现场保管来源。不能只用嫌疑人自行截取的几张截图作为完整不在场证明。

### 11.4 发现者与更早袭击的排除

罗启明的会议在 20:17:40 结束，他随后与前厅的许知微、唐素会合，三人同行到档案室。许知微从前厅开始的采访录像连续记录了这段路及开门过程，现场记录 E01 包含对应原片。门在 20:18 打开时，镜头先拍到已经倒地的顾承舟，随后才有人跨过门槛；三人没有分离、抢先进入或遮挡后实施袭击的机会。

前厅录像与会议录像覆盖到 20:17:40，之后到发现尸体的路程由 E01 接续；不能用一句“全程有录像”省略这一段。泵房录像继续覆盖至发现时刻。

E02 需在指认前明确给出现场检查的有限结论：造成死亡的这次重度钝器伤会立即使人失去自主活动能力，不能先遭受同一致命袭击、再正常步行到前厅签收。它只用于排除更早袭击后继续活动的替代解释，不提供精确死亡时刻，不代替后续正式鉴定。画面保持克制，用调查记录呈现必要信息。

## 14. 关键场景剧本

以下对白是应保留的关键表达与场景走向。开发可以调整口吻和长度，不能改变其已知事实与证据效力。

### 14.1 第一章：到达

**画面：** 三楼前厅。靠墙的雨伞下面积着水。唐素拿着移交清单，第一页的时间还停在 20:00。背景只听得到雨和地下排水泵。

唐素：“刚才大家都听见他了。”

林砚：“你看见他了吗？”

唐素：“没有。广播里。他说原件明早移交。”

林砚：“先记成‘听见顾承舟的声音’。其他的，我们进去看。”

**交互：** 玩家先查看现场，再记录广播证言。首个教学只说明证言与事实的区别，不直接宣布录音诡计。

**现场描述：** 桌旁的铜镇纸落在地上。顾承舟的一只手靠近桌沿，现场照片拍到了掌部夹留的小块透明覆膜残片。门上没有反锁装置。门内出门按钮可见。

**第一章收束：** 拿到 E01、E04、E05、E06，并记录最初证言。任何一个都可回看，不要求先捡镇纸再看门。

### 14.2 第二章：相同的声音

**画面：** 修复间。玩家在采访录音与彩排文件间切换，文字轨同时高亮三个相同的背景事件：纸页擦过桌面、两下轻敲、一声短促的椅脚摩擦。

周予安：“彩排和广播说同一句话，不奇怪。”

林砚：“所以我核对的不只是他说了什么。”

玩家出示文件与播放队列；设备接线显示 20:14 大厅的输入来自播放器，话筒通道没有接入这次输出。

林砚：“这份记录能说明声音从播放器来。还不能说明谁杀了他。”

周予安：“那就把这两件事分开。”

林砚：“正要分开。”

**交互：** 建立 D01，撤销时间线中未经证实的“20:14 本人存活”。已经记下的原证言保留，其解释状态改变。

**第一处转折：** 玩家可以回去询问所有人，而不是自动跳到凶手页面。

### 14.3 第三章：卡片上的名字

沈砚：“日志都在，卡是我的。”

林砚：“我问的是，当时拿着它的是谁。”

玩家可以先拿出借卡登记，也可以先出示沈砚在泵房的完整录像，两种路径均触发核对。

沈砚：“她说只测试一下。我跟着下去处理泵房，想着回来再拿。”

林砚：“你刚才为什么说卡一直在身上？”

沈砚：“借出去，就是我的责任。”

林砚：“借卡是你的责任。谁拿它进了那扇门，是另一件事。”

旧案的调查必须依次回答三个不同问题：

1. **说过什么：** 原始母带记录停止请求，独立值班簿证明该请求被另一端收到。
2. **材料怎样改变：** 修复底稿列出删去的段落与移接的来源，不把普通降噪说成篡改的唯一证据。
3. **谁决定、谁执行：** 周予安签名的技术底稿与罗启明的书面要求分别支持各自行为。

许长川因此获得的不是“因为他是好父亲所以无罪”的判断，而是原本就存在的工作行为得到重新呈现。家书只增加人物的生活，不能充当事故责任证明。

顾承舟的补救不抹去旧错；何闻保留母带也不能让八年沉默消失。许知微可以对他们同时怀有感谢和怨恨，结尾不要求她原谅任何人。

## 19. 报告与结局剧本

### 19.1 报告内容

报告以可核验的主张组成，至少包括：当前实施者、可能作案区间、广播性质、门禁持卡者的判断、本人接触物证、其余人员的机会核查、杀人动机，以及旧案证明程度。

每项可以展开证据。事实已充分时接受等价组织方式，不能因为证据放入了不同位置而判错。

### 19.2 正式结果 A：破晓之前

**条件：** 今案 D06 成立；旧案 D07 / D08 还缺乏充分支持。

周予安作为今案嫌疑人被带走。已取得的旧案材料独立封存，报告明确写出仍待查明的编辑来源或责任关联，不把怀疑填成事实。玩家知道今案完整经过，旧案未完成的调查有明确清单。

许知微站在签收台边，把父亲的名字从文件封面的灰尘里擦出来。

许知微：“这次会留着吗？”

林砚：“原件、提取记录和缺少的部分，都列进去了。”

许知微：“缺少的，也别省。”

**尾声：** 今案调查继续推进。旧案材料进入复核准备，尚不宣称完成责任认定。通关后可返回结案前检查点，补齐旧案；无需重玩已完成的今案。

### 19.3 正式结果 B：被留下的声音

**条件：** D06、D07、D08 均成立。E31 / E32 影响补充尾声内容，不是强制收集门槛。

今案证据链移交。原始母带、独立值班簿、修复底稿、删改指示和转存记录一并进入旧案复查材料。罗启明在旧案中的行为单独调查，不因今案不在场而略过。

何闻把箱子搬到移交台，松手时仍按着箱盖。

何闻：“我一直说，留着总有用。”

许知微：“留着有用。拿出来也要有人做。”

他点头，把手挪开。

唐素在表格“材料性质”一栏写下“原始载体及经核对副本”，又另附一张说明旧签收错误的单子。

许知微：“报道里，我会写他当年要求停下来。”

林砚：“把对应的时间和记录一起写上。”

许知微：“还有其他五个人。名单上不是只有我父亲。”

**最终画面：** 雨停了。修复间的播放器没有再自动播放。六名遇难者的名字，与那句停止接驳的请求一起出现在已封存的材料目录中。

不通过一个按钮立即宣告旧案司法结果。故事完成于事实被还原、责任线索被完整移交，人物的核心问题已经得到回答。

### 19.4 错误指认：报告复核

**条件：** 指认其他人物，或主要证据链存在未解决冲突。

系统展示玩家报告中真正存在的问题。例如指认沈砚时，提示“这份报告没有解释泵房连续记录，仍把卡号当作持卡者身份”。不替玩家把所有错误答案改成正确答案。

林砚：“先撤下这份结论。记录里还有一件事没解释。”

玩家回到推理板，原调查进度保留。此段不宣布一个缺乏依据的指认已经造成定罪，也不作为正式通关结局。

### 19.5 收集与提示不影响正当结论

不设置“好感度高就能证明无罪”“不用提示才有真结局”或“收集所有私人信件才算破案”。E31 / E32 只是补充人物尾声。旧案完整结果依赖真正需要的事实。

## 20. 调查依赖与防卡死

### 20.1 章节开放

- 第一章可取得 E01—E06 中的现场与开场材料，其中 E02 / E03 可稍后回来补看。
- 第二章开放修复间、安保室和基本人物话题，可取得 D01 所需全部材料；E16 会较早呈现表面不在场证明。
- 第三章开放所有路线核查与原始材料调阅。E20 的取得不要求先取得 E22；E11 的取得不要求沈砚先自愿认错。
- 根据入室疑点与虚假检修行程开展物件核查，即可取得 E22；不能以 D04 或认罪为前置条件。
- 旧案材料的调阅依据是正式移交清单与调查权限。何闻、罗启明拒答时，仍可通过登记与旧卷取得必需原件。
- 第四章是推荐的质询与旧案展开阶段，内容开放不强制所有人同顺序完成。
- 第五章允许先结今案，也允许完成旧案后一起提交。进入正式尾声前自动创建检查点。

### 20.2 明确禁止的循环

不能出现“先证明工作证在现场断裂，才能搜到缺角工作证”；不能出现“先让罗承认指示删改，才能拿到证明指示的批注”；不能出现“先认定广播是录音，才允许查看唯一证明它是录音的设备记录”。

关键材料不得因语气选择、先问了另一个人、离开房间或看完某段对白而永久失去。

### 20.3 内容状态

证据收集与核验结果原则上单调累积。推测可以修改，原证言不能被新口供直接覆盖。可重复的调查命令应幂等；重复点击不会重复发奖励、增加隐藏分数或触发两次结局。

## 21. 技术设计与仓库接入

以下是结合现有仓库提出的实现计划，不代表文件已经创建或系统已经接通。

### 21.1 建议结构

```text
games/fog-harbor-files/
  index.html
  vite.config.ts
  src/
    app/            界面、路由、场景与对话呈现
    engine/         纯逻辑、命令、条件求值、推理验证
    content/        案件、人物、证据、证言、对话、结局
    storage/        本地存档、迁移、同步适配
    audio/          录音播放、逐字转录与比对标记
  public/cases/last-recording/
  test/
  browser/
functions/api/games/fog-harbor-files/[[path]].ts
scripts/build-fog-harbor-files.mjs
```

技术方向为 TypeScript strict + Vite + React，数据使用可验证的结构定义。普通界面、文字和证据用 DOM 呈现；只有必要的场景缩放、局部动效使用 Canvas。这个游戏不需要为了一致性引入策略地图的 WebGL 引擎。

### 21.2 游戏状态

存档至少包含：`schemaVersion`、`contentVersion`、`caseId`、`playthroughId`、章节、当前位置、已取得证据、证言版本、已读对话、推理主张及依据、时间线笔记、已见结局、提示记录和设置。

人物动机、真相与待显示文字属于内容包，不被重复复制进每个存档。推理状态只保存用户行为与必要快照，加载时按对应内容版本重建。

核心逻辑不直接依赖 DOM、网络或真实计时。读取证据、询问、出示、建立主张、提交报告均使用显式命令。展示动画不决定游戏事实；跳过动画与完整播放产生相同状态。

### 21.3 内容约束与判定

- 每项素材、人物、证据、条件和对白节点有唯一 ID，所有引用在构建时校验。
- 条件使用数据化表达式和白名单操作，不执行内容中拼接的代码。
- 接受的证据集合按“主张”定义，可以表达 `allOf`、`anyOf` 及已成立的中间命题。
- 错误反馈依据缺失命题生成，从当前已公开信息中措辞，不暴露隐藏证据名。
- 不能只用 `allCluesCollected === true` 或一个总分阈值代替破案验证。
- 游戏答案随静态内容包下发，前端源码不能防止主动查看剧透。本作不承诺反作弊，也不为隐藏谜底强制依赖在线服务。

### 21.4 登录与云存档接入

复用现有服务端主站会话验证与 games 的同步交互。新游戏使用自己的 API 路径、存档命名空间、内容类型与迁移规则。

不能把推理状态硬塞进列国纪元的 `turn`、`era` 或 `GameState` 字段，也不能直接修改旧存档格式。若抽取公共同步能力，应保留两款游戏各自的适配器、原接口兼容性和旧游戏回归验证。

云端方案延续现有 Cloudflare D1 元数据、私有 R2 存档体的模式。对象键与记录包含游戏命名空间和服务端确认的用户身份。用户 A 的存档不得被用户 B 读取或覆盖。

上传具备大小、格式、哈希、内容版本和 revision 校验，账号校验以服务端为准。凭据不进入前端资源、剧情内容、导出的存档或日志。服务器限额在配置中定义并向客户端返回，不在界面编造“无限容量”。

### 21.5 路由、部署与更新日志

- Vite base、资源与内链统一使用 `/fog-harbor-files/`。
- 构建接入现有主站流水线，输出复制到对应独立目录，不能覆盖 `/age-of-nations/`。
- games 首页增加入口，显示案件简介与存档入口；深链接、刷新和返回都要验证。
- HTML 使用可及时更新的缓存策略，哈希素材使用长期缓存；案件内容包按内容版本管理。
- 资源与 API 在 `games.yukino.bond` 下验证，不能只在开发服务器根路径通过。
- 第一次实际产生用户可见网站变化时，同步更新 `src/pages/Changelog.tsx`；同日相关变化合并描述，在同一提交中完成后再推送或部署。
- 本次只编写方案，不添加“游戏已上线”的入口或更新日志。

## 22. 性能、可用性与素材预算

| 指标 | 首发目标与测量边界 |
|---|---|
| 可交互时间 | 在记录的测试设备上，15 Mbps / 80 ms RTT / 4 倍 CPU 降速条件下，冷启动首屏约 3 秒内可操作 |
| 初始 JS | 初始必须加载的 JavaScript 合计不超过 1 MB gzip |
| 首屏传输 | 关键首屏资源合计目标不超过 2 MB，后续场景、音频和长对白按需加载 |
| 全案件资源 | 首轮目标不超过 45 MB；需列出图像、音频、字体的实际分项体积 |
| 常规反馈 | 按钮、物件和证据操作无可感知的长时间阻塞；较重比对任务移出主线程 |
| 场景动效 | 桌面目标 60 FPS，中端手机不低于稳定可用水平；低性能设备可关闭动效 |
| 文字阅读 | 字号可调，长文本可滚动、可复制；不强制逐字等待 |
| 无障碍 | 键盘导航、可见焦点、非颜色提示、减少动态效果、文字版音频和证据观察 |
| 页面恢复 | 切后台、锁屏、刷新后恢复到最近已成功写入的调查状态与阅读位置 |

核心信息不能依赖网络字体或第三方在线图片。音频在离线未就绪时有文字替代；关键画面未加载时有可重试状态，不能用一个空白热点继续剧情。

## 23. 剧本与程序验证

### 23.1 剧本桌面验证

在正式美术和前端之前，用本稿的时间线、证据原文和地图走一遍案件：

1. 对每个人逐一假设其实施杀人，写出与证据的冲突。
2. 查出所有“只有作者知道”的前提；必要前提必须在指认前公开。
3. 检查行程、借卡、钥匙、日志事件类型和断口图像是否互相一致。
4. 检查旧案证据能否分别证明原话、剪辑与指示者，避免把它们混成一句“有黑幕”。
5. 检查现在的真相能否在不听认罪、不读私人家书的情况下成立。
6. 找从开场到两种正式结果的完整路线，以及错误理论返回调查的路线。

本稿已给出逻辑检查依据与反证表；它仍需在证据全文、美术和交互完成后再次验证，不能把文档自洽当作已完成玩家盲测。

### 23.2 必须自动验证的内容

- ID 唯一、引用有效、条件和跳转节点存在。
- 必需证据与正式结果可达，没有互相锁定的循环条件。
- 多种合法收集顺序产生等价的已知事实；重复命令不改变结论。
- 正确主张的等价充分证据组合可被接受；缺关键前提的组合不会误判。
- 门禁卡归属不能代替持卡者身份；音频出现不能代替本人存活。
- 错误指认不能落入正式正确结局。
- 存档往返、版本迁移、损坏文件拒绝、IndexedDB 写入失败与恢复。
- 两台设备并发、离线补传、账号切换、会话过期、删除记录与冲突保留。
- 云 API 的用户隔离、游戏命名空间隔离、revision 校验。
- 对话跳过、静音与完整播放产生相同调查状态。

### 23.3 必须人工试玩的内容

- 按推荐顺序、逆向收集顺序、主动提前怀疑周予安三种方式完成调查。
- 静音完成、只用键盘完成、手机竖屏完成。
- 中途刷新、锁屏、断网，核对保存状态是否说实话。
- 至少一轮未读谜底的试玩，记录首次卡住的问题、误解与提示需求。
- 记录真实通关时间与有效调查占比；人物对白、界面和线索展示的不足都需要修正。
- 对照素材逐一检查时间、工作证完整与缺角状态、门窗、人物位置；不能只测程序条件。

测试不声称数学上排除了任意虚构世界。目标是在已公开的本案规则内，答案唯一、理由完整，反例能被现有证据回应。

## 24. 开发里程碑与完成定义

### M0：方案与全文内容定稿

确认本稿中的名称、氛围、玩法和首案方向。随后补完运行时证据全文、全部对白分支、提示、报告反馈与资产清单，先用文本流程验证逻辑。

**完成条件：** 32 项证据、24 条核心证言、8 个推理和全部结果均有实际内容；没有决定性事实留待开发中临时补写。

### M1：完整调查原型

完成七个地点、人物对话、证据档案、推理板、时间线、报告、本地存档与文字音轨。素材可暂用明确标记的占位图，但首案必须能从头走到结尾。

**完成条件：** 今案及旧案均可解，错误指认可恢复，开放顺序不会卡死。这个阶段只算原型，不作为正式上线完成。

### M2：正式首案表现与适配

替换正式场景、立绘、道具放大图、关键录音与环境音，完成手机竖屏、键盘、减少动态效果、完整资源包离线与恢复验证。

**完成条件：** 画面达到第 7 节要求；盲测能理解关键材料，实际流程不是只有简短故事和几个选择题。

### M3：账号、云同步与生产接入

接通主站登录与本游戏的隔离存档，同步冲突、退出、离线与故障路径均完成；加入 games 入口、子路径构建和相应更新日志。

**完成条件：** 访客完整游玩、账号跨设备恢复都能验证，既有列国纪元入口与存档没有回归问题。

### M4：验收后发布

在实际 games 域名检查资源路径、刷新、缓存、账号与手机体验，完成最终剧本复查和盲测修订。按用户后续明确的开发与发布指令执行。

**正式首发必须包含 M0—M4 的相应成果。** 不把云同步、完整结局或正式画面临时改成“以后再补”却宣布已按本稿完成。
