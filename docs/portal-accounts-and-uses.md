# 主站账号与设备清单

主站默认使用 Yukino Mail 账号登录。注册入口指向 `https://mail.yukino.bond/`，完成邮箱注册后可在主站输入同一邮箱和密码。

## 身份验证

- 主站服务端请求邮箱站的 `/api/login`，再用邮箱站会话请求 `/api/my/loginUserInfo`，核对用户 ID 与邮箱。
- 邮箱密码不写入主站数据库，邮箱会话不会返回浏览器。主站签发自己的七天会话；退出主站会清除主站登录状态。
- `mail_identities` 通过稳定的邮箱站用户 ID 关联主站用户。已有相同邮箱的主站账号保留用户 ID、内容关联及原主站权限。邮箱站删除账号后重新注册产生的新 ID 不会自动继承旧主站资料。
- 邮箱站的超级管理员由 `type = 0`、`role.name = admin` 和通配权限共同确认。普通邮箱用户首次登录获得普通用户权限。原主站管理员权限保留；仅来自邮箱站的管理员权限在下次登录时重新核实。
- 原主站账号可在登录页选择“原主站账号”，使用原主站密码。邮箱验证失败时不会自动尝试原主站密码。
- 服务端每次授权都检查数据库中的当前角色。公开开发签名密钥已移除，缺少 `JWT_SECRET` 时拒绝验证和签发会话。

部署流程检查生产环境的 `JWT_SECRET`，保留现有加密密钥；未配置加密密钥时生成并保存私密签名密钥，不在日志中输出其值。本地开发需在忽略版本控制的 `.dev.vars` 中配置 `JWT_SECRET`。

## 设备页

访客与普通用户可浏览 `/uses`；管理员登录后可使用“编辑清单”，管理分类、图标、条目和页面介绍，点击“保存清单”发布。管理控制台也提供设备清单入口。

- `/api/uses` 的 GET 返回公开内容和服务端核实的编辑权限。
- PUT 在服务端检查会话与管理员角色，验证内容长度、图标、条目标识及版本。
- 数据存入绑定的 `yukino-portal` D1 数据库的 `site_content` 表。首次编辑前使用原设备清单作为默认值。
- 保存使用版本比较；遇到其他窗口已发布的新版本时返回 409，保留当前编辑草稿并提示重新读取页面。
- 新表通过绑定数据库执行幂等创建，保留原有用户与内容；`schema.sql` 包含相同表定义。

`src/test/uses-editor.test.tsx` 覆盖公开浏览、管理员发布、增删分类、取消草稿和失败保留草稿。两组检查在网站部署前运行。
